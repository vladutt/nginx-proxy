# nginx-proxy

A version-controlled nginx reverse proxy for one Ubuntu server with Docker.
Each project on the server gets its own subdomain (`app.<DOMAIN>` → a
container or a local port). HTTPS uses **one wildcard certificate**
(`<DOMAIN>` + `*.<DOMAIN>`) from Let's Encrypt via **Cloudflare DNS-01**.

Everything is driven by `.env`; no domain or project is hard-coded.

## Layout

| Path | Purpose |
|------|---------|
| `docker-compose.yml` | `nginx` + `certbot` (dns-cloudflare) services, external `proxy` network |
| `nginx/nginx.conf` | Global settings (gzip, timeouts, log format, `server_tokens off`, Cloudflare real IP) |
| `nginx/snippets/` | Shared includes: `proxy-headers`, `ssl-cert` (wildcard paths), `ssl-params`, `security-headers`, `websocket` (opt-in), `cloudflare-realip` |
| `nginx/conf.d/00-default.conf` | Catch-all: unknown hosts get `444`, unknown TLS SNI is rejected |
| `nginx/conf.d/<sub>.<DOMAIN>.conf` | One file per site (generated by `add-site.sh`) |
| `templates/site.conf.template` | Site template used by `add-site.sh` |
| `examples/app.example.conf` | Documentation-only example; **not** loaded by nginx |
| `secrets/cloudflare.ini.example` | Placeholder for the Cloudflare API token |
| `scripts/` | `init-cert.sh`, `add-site.sh`, `remove-site.sh`, `update-cloudflare-ips.sh` |

## Prerequisites

- Ubuntu server with Docker and the Compose plugin; ports 80 and 443 open.
- DNS for the domain on **Cloudflare**, with `<DOMAIN>` and `*.<DOMAIN>`
  records pointing at the server (orange or grey cloud, see below).
- A Cloudflare API token with **only** `Zone → DNS → Edit` on that one zone.
  No other permissions are needed.

## First setup (order matters)

```sh
# 1. network shared with the proxied containers (name must match PROXY_NETWORK)
docker network create proxy

# 2. configuration and the Cloudflare token
cp .env.example .env                                   # set DOMAIN, LETSENCRYPT_EMAIL
cp secrets/cloudflare.ini.example secrets/cloudflare.ini
$EDITOR secrets/cloudflare.ini                         # paste the token
chmod 600 secrets/cloudflare.ini

# 3. issue the wildcard certificate (DNS-01, takes ~1 minute)
scripts/init-cert.sh

# 4. start
docker compose up -d
```

`.env` and `secrets/cloudflare.ini` are git-ignored; never commit them. Set
`LETSENCRYPT_STAGING=1` first to try the flow against the staging CA (untrusted
certs, no rate limits); when switching to production re-run
`scripts/init-cert.sh --force-renewal`. `init-cert.sh` passes extra arguments
to certbot, so `scripts/init-cert.sh --dry-run` is also available.

`init-cert.sh` wraps:

```sh
docker compose run --rm --entrypoint certbot certbot certonly --dns-cloudflare \
  --dns-cloudflare-credentials /run/secrets/cloudflare.ini \
  --cert-name wildcard -d <DOMAIN> -d '*.<DOMAIN>' ...
```

The certificate lineage is always named `wildcard`, so the nginx config
(`snippets/ssl-cert.conf`) never contains the domain. With no sites,
nginx starts fine even before a certificate exists.

## Adding a project in 3 steps

1. **Make the project reachable by nginx.** Container: put it on the proxy
   network (`docker network connect proxy <container>`, or add the external
   `proxy` network to its own compose file). Host service: listen on `0.0.0.0`
   or the Docker bridge address (not only `127.0.0.1`).
2. **Generate the site:**
   ```sh
   scripts/add-site.sh app app:3000            # app.<DOMAIN> -> container app, port 3000
   scripts/add-site.sh app host.docker.internal:3001   # service on the host
   scripts/add-site.sh app app:3000 --ws       # WebSocket app
   scripts/add-site.sh app                     # pick from running containers
   ```
   The script validates the input, writes `nginx/conf.d/app.<DOMAIN>.conf`,
   runs `nginx -t`, and reloads only if it passes (otherwise it rolls back).
   `--force` overwrites, `--dry-run` prints the config only.
3. **Commit** the new file (it contains no secrets) and check
   `https://app.<DOMAIN>`.

Container names resolve at request time through Docker DNS, so nginx still
starts if a project container is down (it returns 502 until it is back).
`examples/app.example.conf` shows what the script generates.

## Removing a project

```sh
scripts/remove-site.sh <subdomain>
```

Deletes the site file, runs `nginx -t`, reloads (restoring the file if the test
fails). The wildcard certificate is shared and is not touched.

## Certificate renewal

The `certbot` container runs `certbot renew` every 12 hours; certbot only
renews when the certificate is within 30 days of expiry and reuses the saved
Cloudflare credentials. Because certbot cannot signal the `nginx` container,
the nginx container acts as the deploy hook: it checks the checksum of
`live/wildcard/fullchain.pem` every minute and runs `nginx -s reload` as soon
as it changes. No Docker socket is shared. Test renewal with:

```sh
docker compose run --rm --entrypoint certbot certbot renew --dry-run
```

## Cloudflare proxy (orange cloud)

- Set the SSL/TLS mode to **Full (strict)**. The origin has a valid Let's
  Encrypt certificate, so strict validation works.
- `snippets/cloudflare-realip.conf` is included globally: connections from
  Cloudflare's ranges have their client address taken from `CF-Connecting-IP`,
  so logs and `X-Real-IP` / `X-Forwarded-For` show the real visitor. Requests
  from other addresses cannot spoof it.
- Cloudflare's ranges change rarely. Refresh them with
  `scripts/update-cloudflare-ips.sh` (fetches `ips-v4` / `ips-v6`, runs
  `nginx -t`, reloads, restores the old file on failure), then commit the
  diff. Run it now and then, or from cron.
- WebSockets work through Cloudflare (enabled by default); use `--ws` on the
  sites that need them. Cloudflare's upload limit and 100 s proxy timeout still
  apply on the free plan.

## Validation

```sh
docker compose config -q
docker compose run --rm --no-deps nginx nginx -t   # or: docker compose exec nginx nginx -t
shellcheck -x scripts/*.sh
```

Routing check without DNS:

```sh
curl -sI -H 'Host: app.<DOMAIN>' http://localhost/                      # 301 to https
curl -sk --resolve app.<DOMAIN>:443:127.0.0.1 https://app.<DOMAIN>/     # proxied content
curl -sI -H 'Host: unknown.<DOMAIN>' http://localhost/                  # connection closed (444)
```

## Troubleshooting

- **`cannot load certificate ... live/wildcard/fullchain.pem`**: the cert was
  not issued yet (run `scripts/init-cert.sh`), or `certbot/conf` was deleted.
- **certbot: "Unable to determine zone_id" / auth errors**: the token is wrong,
  or lacks `Zone → DNS → Edit` for this zone; check `secrets/cloudflare.ini`
  (mode 600, no quotes around the token).
- **certbot times out waiting for DNS**: raise
  `--dns-cloudflare-propagation-seconds` by passing it to `init-cert.sh`.
- **502 Bad Gateway**: upstream down, wrong port, or the container is not on
  the `proxy` network (`docker network inspect proxy`).
- **`host not found in upstream`** in `nginx -t`: a static upstream
  (`host.docker.internal` / IP) does not resolve; check `extra_hosts`.
- **Host service unreachable**: bind it to `0.0.0.0`/the bridge address and
  allow the Docker bridge in the host firewall (`ufw`).
- **Redirect loop behind Cloudflare**: SSL mode is "Flexible"; set it to
  "Full (strict)".
- **Logs**: `docker compose logs -f nginx`. Container logs are rotated by
  Docker (`json-file`, 5 files of 10 MB per service, set once in
  `docker-compose.yml`); change `max-size` / `max-file` there. Recreate the
  containers (`docker compose up -d`) for a change to apply.

## Secrets

`.env` and `.env.*` (except `.env.example`), everything in `secrets/` (except
`*.example`), `certbot/conf/` (certificates and keys), `*.pem`, `*.key` and
`logs/` are git-ignored. Never commit them.
