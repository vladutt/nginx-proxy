# nginx-proxy

A version-controlled nginx reverse proxy for one server. Each project on the
server gets its own subdomain (`app1.example.com` → a container or a local
port), with HTTPS from Let's Encrypt (HTTP-01, webroot).

Everything is driven by `.env`; no domain or project is hard-coded.

## Layout

| Path | Purpose |
|------|---------|
| `docker-compose.yml` | `nginx` + `certbot` services, external `proxy` network |
| `nginx/nginx.conf` | Global settings (gzip, timeouts, log format, `server_tokens off`) |
| `nginx/snippets/` | Shared includes: proxy headers, TLS, security headers, WebSocket (opt-in), ACME |
| `nginx/conf.d/00-default.conf` | Catch-all: unknown hosts get `444`, unknown TLS SNI is rejected |
| `nginx/conf.d/<sub>.<DOMAIN>.conf` | One file per site (generated by `add-site.sh`) |
| `templates/` | `site.http.conf.template` (stage 1) and `site.conf.template` (HTTPS) |
| `scripts/add-site.sh`, `remove-site.sh` | Add / remove a site, validate, reload |
| `certbot/conf`, `certbot/www` | Certificates and ACME webroot (git-ignored, created at runtime) |

## Prerequisites

- Docker with the Compose plugin; a server with ports 80 and 443 open.
- DNS: an `A`/`AAAA` record for every subdomain (or a wildcard) pointing at the server.
- Bash 3.2+ (the scripts run on macOS and Linux). Optional: `shellcheck`.

## First setup

```sh
cp .env.example .env          # then edit DOMAIN and LETSENCRYPT_EMAIL
docker network create proxy   # must match PROXY_NETWORK in .env
docker compose up -d
```

`.env` is git-ignored. Set `LETSENCRYPT_STAGING=1` while testing to use the
Let's Encrypt staging CA (certificates are not trusted, but no rate limits).

## Adding a project

```sh
scripts/add-site.sh <subdomain> [upstream] [--ws] [--force] [--issue]
```

The hostname is `<subdomain>.<DOMAIN>`. The upstream is `host:port`:

- **Container on the proxy network**: `myapp:3000`. Attach it first:
  `docker network connect proxy myapp` (or add the `proxy` network to its own
  compose file). The name is resolved at request time via Docker DNS, so nginx
  still starts if that container is down (requests get 502 until it is back).
- **Service on the host** (not in a container): `host.docker.internal:3001`
  (`localhost`/`127.0.0.1` are rewritten to this). The service must listen on
  `0.0.0.0` (or the Docker bridge address); on Linux a service bound only to
  `127.0.0.1` is not reachable from the container.
- **No upstream**: the script lists running containers (`docker ps`) and
  lets you pick one, or choose `0` for a host port.

`--ws` includes `snippets/websocket.conf` for that site (WebSocket only where
needed). `--force` overwrites an existing site file. `--issue` runs certbot
for you.

### Certificate bootstrap (two stages)

A `listen 443 ssl` block cannot load before its certificate exists, which
would break nginx for *all* sites. So `add-site.sh`:

1. If no certificate exists yet, writes an **HTTP-only** file (ACME challenge
   plus `503` for everything else), validates, reloads, and prints the certbot
   command.
2. After the certificate is issued, writes the **full HTTPS** file (80 → 443
   redirect, TLS, security headers, proxy). Either pass `--issue` to do both
   in one go, or issue manually and re-run the same command with `--force`.

If `nginx -t` fails at any step, the previous file is restored (or the new
file removed) and nothing is reloaded.

Manual certificate command (as printed by the script):

```sh
docker compose run --rm --entrypoint certbot certbot certonly --webroot \
  -w /var/www/certbot -d app1.example.com --email you@example.com \
  --agree-tos --no-eff-email --non-interactive
```

Commit the new `nginx/conf.d/<host>.conf` afterwards (it contains no secrets).

## Removing a project

```sh
scripts/remove-site.sh <subdomain> [--purge-cert]
```

Deletes the site file, runs `nginx -t`, reloads (restoring the file if the
test fails). The certificate is kept unless `--purge-cert` is given.

## Certificates and renewal

The `certbot` container runs `certbot renew` every 12 hours. The `nginx`
container reloads itself every 6 hours, so renewed certificates are picked up
within a few hours without any socket access between containers. Force a
reload any time with `docker compose exec nginx nginx -s reload`. Check
renewal with:

```sh
docker compose run --rm --entrypoint certbot certbot renew --dry-run
```

## Validation

Always validate before reloading or deploying:

```sh
docker compose run --rm --no-deps nginx nginx -t   # or: docker compose exec nginx nginx -t
docker compose exec nginx nginx -s reload
shellcheck -x scripts/*.sh
```

Quick routing check without DNS:

```sh
curl -sk --resolve app1.example.com:443:127.0.0.1 https://app1.example.com/
curl -sI -H 'Host: app1.example.com' http://localhost/   # 301 to https
curl -sI -H 'Host: unknown.example.com' http://localhost/ # connection closed (444)
```

## Troubleshooting

- **`host not found in upstream`** in `nginx -t`: you used a static upstream
  (`host.docker.internal` / IP) that does not resolve. Check `extra_hosts` in
  the compose file. Container names are resolved lazily and do not fail here.
- **502 Bad Gateway**: the upstream is down, on another port, or the container
  is not on the `proxy` network (`docker network inspect proxy`).
- **Host service unreachable**: bind it to `0.0.0.0` (or the Docker bridge
  address), and check the host firewall allows the Docker bridge.
- **Certbot fails with 404/timeout**: DNS not pointing here, port 80 blocked,
  or the site file is missing its stage-1 block. Look at
  `docker compose logs nginx`.
- **nginx will not start after a cert was deleted**: remove the site file
  (`remove-site.sh`) or re-issue the certificate; a 443 block without its
  certificate fails `nginx -t`.
- **Logs**: `docker compose logs -f nginx`.

## Secrets

`.env`, `certbot/conf/` (certificates and keys), `*.pem`, `*.key` and `logs/`
are git-ignored. Never commit them.
